# Release template (copy for every new version)

## vX.Y.Z — YYYY-MM-DD

**Status:** Stable / Beta / Prototype  
**Download:** Link to release archive

### New features
- Describe the features added, with enough detail to demonstrate them.

### Fixes
- Which previous version had the bug?
- What users experienced and what changed.

### Known issues
- List remaining problems and workarounds. Don't claim a bug is fixed unless checked.

### Testing
- Windows versions, launcher method, and what was actually tested.

### Screenshots / demo
- Add only real screenshots and demos from this version.

## Upload checklist for a NEW project

- Create a **separate public repository** for each real project.
- Add code, launch/readme instructions, screenshots, license and changelog.
- Do **not** publish API keys, passwords, private data, account credentials, admin keys, access tokens, `.env` files, or copyrighted media without permission.
- Upload downloadable ZIPs as release assets and assign version tags like `v1.0.0`, `v1.1.0`, `v2.0.0`.
- Keep existing versions instead of silently overwriting them.
- Add the repo link to a portfolio or GitHub profile README.
